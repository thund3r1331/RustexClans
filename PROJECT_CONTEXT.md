## 1. О проекте: что это и для чего

### 1.1. Предметная область (КРИТИЧЕСКИ ВАЖНО)
- **Rustex Remake** — это игра с механикой выживания и клановым противостоянием (клановые войны, строительство баз по квадратам карты, рейды ракетами и взрывчаткой, лутание крейтов, сбитие патрульного вертолета, вайпы).
- **Это НЕ классический Rust от Facepunch!** Все игровые события, ники игроков, кланы, видеозаписи (откаты) и механики относятся к игре **Rustex Remake**. В текстах и интерфейсе проект упоминается строго как **игра Rustex Remake** (не сервер и без упоминания Minecraft).
- **RustexClans (CRL — Clan Rating Ladder)** — соревновательный веб-портал и ладдер (в стиле HLTV / киберспортивных таблиц лидеров) для кланов Rustex Remake.

### 1.2. Основная цель платформы
1. **Прозрачный рейтинг кланов**: Автоматический расчет рангов, очков (CRL), динамика позиций (поднялся/опустился), тиры (Tier 1, Tier 2, Tier 3).
2. **Публичный аудит (Audit Log)**: Журнал всех рейдов и начислений очков с указанием причины, ссылок на видеопруфы (YouTube / Discord) и ников модераторов, подтвердивших операцию.
3. **Презентация кланов**: Профили кланов с тегом, описанием, составом игроков, логотипами, ссылками на Discord и графиком истории рейтинга.
4. **Модерация**: Скрытая панель управления для команды модераторов (администраторов) для добавления кланов, корректировки очков и фиксации результатов.

## 2. Регламент и правила начисления очков (Scoring System)

Лимит очков: **1 000 CRL** (максимум) • Старт нового клана: **0 CRL**.

### Таблица начисления и списания очков:
| Действие | Очки | Описание |
| :--- | :---: | :--- |
| **Победа: рейд клана выше в рейтинге** | **+20 CRL** | Успешный онлайн-рейд соперника с более высоким рейтингом |
| **Победа: рейд клана ниже в рейтинге** | **+15 CRL** | Успешный онлайн-рейд соперника с более низким рейтингом |
| **Поражение: проигрыш клану выше в рейтинге** | **-15 CRL** | Поражение от более сильного соперника (меньший штраф) |
| **Поражение: проигрыш клану ниже в рейтинге** | **-20 CRL** | Поражение от более слабого соперника (максимальный штраф за апсет) |
| **Забирание патрульного вертолёта** | **+7 CRL** | Сбитие и успешное удержание ящиков вертолёта |
| **Забирание крейта** | **+5 CRL** | Взятие крейта при активном онлайне |
| **Рекорды ракет** | **+3 CRL** | Подтвержденный рекорд по выпущенным ракетам при рейде |
| **Заняли первое место в топе** | **+2 CRL** | Бонус за взятие 1-й строчки в ладдере |

> **Связка атакующий / защитник в рейде**:
> - Если Клан А (ниже в топе) побеждает Клан Б (выше в топе): Клан А получает **+20 CRL**, а Клан Б теряет **-20 CRL** (так как проиграл клану ниже себя).
> - Если Клан А (выше в топе) побеждает Клан Б (ниже в топе): Клан А получает **+15 CRL**, а Клан Б теряет **-15 CRL** (так как проиграл клану выше себя).

### Обязательные правила турнира:
1. **Критерий онлайн-рейда**: Рейд засчитывается только в онлайне, когда **не менее половины состава клана находится на сервере**. Офлайн-рейды строго запрещены.
2. **Квадрат застройки**: Каждый клан на старте вайпа обязан зафиксировать свой квадрат карты в Discord-канале ладдера.
3. **Антирейд своей базы**: Если клан шваркнули (зарейдили) во время активного антирейда своей базы, **очки не уменьшаются при наличии полного отката (видеозаписи)**.
4. **Рейды альянсом**: При совместном рейде альянсом заработанные очки делятся **пополам** между союзными кланами.
5. **Состав клана**: Минимальное количество участников для участия в ладдере — **10 игроков**.
6. **Правило тай-брейка**: При равенстве очков (например, оба клана имеют 1 000 CRL) выше располагается тот, кто набрал очки раньше по времени (`points_reached_at`).

## 3. Технологический стек

### Frontend (`frontend/`)
- **Фреймворк**: React 18, TypeScript, Vite.
- **Стилизация**: Tailwind CSS, киберпанк / Rust dark-theme эстетика, Bento-grid сетка.
- **Компоненты**:
  - `Navbar.tsx` — статус ладдера, кнопка подачи заявки в Discord, профиль модератора.
  - `LadderView.tsx` — общая рейтинговая таблица с фильтрами по тирам и поиском.
  - `PodiumView.tsx` — презентация топ-3 кланов сезона с анимированными эффектами.
  - `RaidsView.tsx` — лог рейдов и аудит начислений.
  - `RulesView.tsx` — регламент и правила турнира.
  - `ClanDetailModal.tsx` — детальная карточка клана с графиком рейтинга.
  - `AdjustModal.tsx` — модалка модератора для изменения очков с готовыми пресетами.
  - `CreateClanModal.tsx` — форма регистрации клана с загрузкой логотипа.
  - `LoginModal.tsx` — форма входа модераторов (глаз для скрытия пароля, автоматический `trim`).
  - `ParticleCanvas.tsx` — интерактивный фоновый холст на HTML5 Canvas.
- **Вход модератора**: Секретная комбинация клавиш `zxce` на клавиатуре.

### Backend (`backend/`)
- **Фреймворк**: FastAPI (Python 3.11+, асинхронный).
- **База данных**: SQLite + `aiosqlite` (SQLAlchemy 2.0 Async ORM).
- **Конфигурация SQLite**: Включен режим `PRAGMA journal_mode=WAL;`, `PRAGMA synchronous=NORMAL;` для высокой производительности и отсутствия блокировок базы при параллельных запросах.
- **Архитектура бэкенда**:
  - `app/api/clans.py` — CRUD операции с кланами, пересчет рангов, изменение рейтинга.
  - `app/api/auth.py` — эндпоинты входа (`/login`), профиля (`/me`), смены пароля (`/change-password`).
  - `app/api/uploads.py` — безопасная загрузка логотипов.
  - `app/api/leaderboard.py` — публичный лидерборд.
  - `app/api/audit.py` — публичный аудит-лог рейтинга.
  - `app/services/ranking.py` — сервисная логика сортировки, тиров и тай-брейков.
  - `manage_admins.py` — консольная утилита управления администраторами через SSH.

## 4. Архитектура безопасности

В проекте реализована строгая политика безопасности:

1. **Изоляция учетных записей (No Web User Creation)**:
   - В веб-API **нет эндпоинта создания пользователей**.
   - Администраторы и модераторы добавляются и редактируются **строго локально на сервере через SSH**:
     ```bash
     python manage_admins.py --set <логин> <пароль> --role admin
     python manage_admins.py --remove <логин>
     python manage_admins.py --list
     ```
2. **Пароли и хеширование**:
   - Пароли хранятся исключительно в виде односторонних криптографических хешей `bcrypt` с индивидуальной солью.
   - В коде проекта нет захардкоженных паролей.
3. **Защита от подбора паролей (Brute-Force Rate Limiter)**:
   - Максимум 5 неудачных попыток с одного IP за 15 минут. При превышении — блокировка с `HTTP 429 Too Many Requests`.
   - Искусственная задержка 1.0 сек на каждую неудачную попытку для предотвращения перебора по словарю.
   - Автоматический `trim()` логина и пароля на бэкенде и фронтенде (защита от лишних пробелов буфера обмена мобильных устройств).
4. **JWT-сессии**:
   - Токены подписаны секретным 64-байтным ключом `SECRET_KEY`, хранящимся в `.env`.
   - Время жизни токена ограничено до **24 часов** (`ACCESS_TOKEN_EXPIRE_MINUTES = 1440`).
   - Смена `SECRET_KEY` на сервере мгновенно инвалидирует абсолютно все активные токены.
5. **Закрытый Swagger / OpenAPI**:
   - Эндпоинты `/docs`, `/redoc` и `/openapi.json` отключены (`docs_url=None`, `redoc_url=None`, `openapi_url=None`).
6. **Безопасность загрузки файлов**:
   - Разрешены только растровые изображения: `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`.
   - **Формат `.svg` запрещен** во избежание Stored XSS атак.
   - Проверяется фактический размер (строго до 5 МБ) и сигнатуры magic bytes заголовков.
7. **CORS**:
   - Звездочка `*` удалена. Разрешены только доверенные домены (`https://rcl.zelenskiy.xyz`, `https://zelenskiy.xyz`, прямой порт `:8080`, локалхост для разработки).
8. **Автоматические резервные копии**:
   - На VDS развернут скрипт `/opt/rustexclans/backup_db.sh`.
   - Планировщик `cron` ежедневно в 03:00 UTC делает снапшот базы в `/opt/rustexclans/backups/rustex_YYYYMMDD_HHMMSS.db` (хранятся последние 14 копий).

## 5. Инфраструктура и продакшен

- **Сервер**: Ubuntu 24.04 LTS VDS (`64.188.64.14`).
- **Веб-сервер / Reverse Proxy**: Caddy (автоматические Let's Encrypt SSL-сертификаты).
  - Порт `:3000` — основной сайт (`zelenskiy.xyz`).
  - Порт `:8000` — бэкенд FastAPI RustexClans (поддомен `rcl.zelenskiy.xyz`).
  - Порт `:8080` — прямой порт для доступа к ладдеру.
- **Системный сервис**: Systemd юнит `rustexclans.service`:
  ```ini
  WorkingDirectory=/opt/rustexclans/backend
  ExecStart=/opt/rustexclans/venv/bin/python main.py
  Environment="ENV=production"
  Restart=always
  ```
- **Раздача SPA фронтенда**:
  FastAPI самостоятельно раздает скомпилированные статические файлы `frontend/dist` с поддержкой SPA Fallback (любой не-API путь отдает `index.html`).

## 6. Правила и чеклист для AI-агентов при модификации проекта

При выполнении любых задач в этом репозитории AI-агент **ОБЯЗАН** соблюдать следующие правила:

1. **Не путать с Rust Facepunch**: Помнить, что проект относится к независимой игре **Rustex Remake** (не упоминать Minecraft и не называть сервером).
2. **Гигиена Git**:
   - **Никогда** не выполнять слепой стейджинг (`git add .` или `git add -A`). Добавлять только файлы, относящиеся к текущей задаче.
   - **Никогда** не коммитить пароли, секреты, токены или файлы `.env` в Git.
3. **Автономная валидация после изменений**:
   - При правках во фронтенде: перейти в папку `frontend/` и выполнить `npm run build` (проверяет типы TypeScript и сборку Vite).
   - При правках в бэкенде: запустить `backend/.venv/Scripts/python.exe backend/tests/test_api.py` (или соответствующий путь к Python) и убедиться в успешном прохождении тестов.
4. **Сохранение стиля и комментариев**:
   - Использовать точечные правки (Surgical Edits), не затирать существующую логику, комментарии и структуру.
5. **Безопасность**:
   - Не возвращать открытый Swagger `/docs` в продакшен.
   - Не ослаблять валидацию загружаемых файлов и rate limiting.
6. **Согласование с пользователем**:
   - При спорных или архитектурных решениях всегда сначала советоваться с пользователем и предлагать рекомендуемый вариант.
